## Invariants and indexes

- Every source, configuration, corpus, artifact and connection belongs to one project. All service lookups check this relationship.
- Sources are immutable content revisions. Reuploading a changed file creates another source.
- A config revision used in a run is immutable. Save an edit as a new row.
- A new configuration starts a family at revision 1. Saving with based_on_config_id joins that family and allocates the next revision transactionally; no historical row changes.
- Unique run_id plus seq and unique event_id protect event order and deduplication.
- Index events on run_id plus seq, runs on project_id plus created_at, jobs on status plus created_at, and artifacts on project_id plus content_sha256.
- Add preparation uniqueness for project_id plus requirements_sha256 while an index artifact is active. Configuration-to-bundle bindings may refer to the same artifact set.
- Foreign keys restrict accidental deletion. A dedicated deletion service performs the confirmed dependency cascade and external-store cleanup.
- config_snapshot matches the strict pipeline schema. Separate provenance_json records sanitized provider identity fingerprints, model/parser revisions, runtime revision, prompt hash, artifact IDs and cache state. Secret values are excluded.

## File ingestion

The API validates declared and detected file type, maximum byte size and safe display name, writes to a server-generated temporary path, computes the SHA-256 digest, then enqueues ingestion. Source states are processing, ready, failed, deleting and deleted. Failed sources can be removed or uploaded again; their partial artifacts cannot enter a ready corpus.

Use a pinned parser such as Docling through a small parser interface. PDF page extraction must retain 1-based physical page numbers. Store printed page labels separately when available. Markdown/text provenance records UTF-8 source identity, Unicode code-point offsets and line ranges. Text normalization used for retrieval must preserve a mapping to inspectable extracted source text.

For v1 a PDF requires a usable text layer. Mark image-only pages as extraction warnings; reject a document whose required content cannot be extracted without OCR. Do not show an empty parsed file as ready. Detect password protection, corrupt PDFs, archive bombs and timeouts.

Separate raw bytes, canonical extracted text, structural metadata, chunk variants and index artifacts. Parsing once does not imply every adapter must use the same parser: PageIndex builds its own tree from original PDFs. Record this preprocessing difference in comparison metadata.

## Chunking

Default strategy fixed_tokens uses a 512-token target and 64-token overlap. A second strategy headings respects Markdown headings and available PDF section boundaries before applying the same size limit. Both preserve original offsets and never merge distinct sources.

Use a pinned tokenizer revision recorded in each variant. A practical default is tiktoken cl100k_base for chunk boundaries, with separate provider-aware validation for embedding and generation limits. These are chunker token units and are not asserted to match every model's tokenizer.

Choose splits using source character boundaries and measured token count. Verify that concatenated excerpt text maps exactly to the recorded source interval; avoid decoding arbitrary partial Unicode tokens. Child and parent variants obey document 04.

Stable candidate identity is SHA-256 of the portable source ID, source content hash, parser/chunker/tokenizer revision, source location and exact text, encoded canonically. Do not include the deployment's project ID in this portable identity. An export preserves portable source IDs through its source manifest and verifies source hashes before reuse. A shared sentence appearing twice remains two distinct source locations.

## Preparation fingerprints

Compute the canonical requirements hash from only preparation-affecting inputs. It includes parser/chunker versions, document hashes, tokenizer settings, embedding provider and model identity and dimension, task prefixes, and index algorithm settings. Reranking top-k, answer prompt and temperature normally do not require re-embedding.

The bundle stores the resolved ready artifact IDs plus the full config binding. Provider identity includes a hash of the sanitized endpoint, model, task settings and relevant profile revision. Credential rotation alone does not change that identity. Changing a profile's model or endpoint invalidates affected bindings and requires preparation again. Never reuse a bundle from another corpus merely because its filenames match. Unknown remote model revisions remain unknown in provenance; the user can force rebuilding.

Qdrant collection design may group vectors by dimension and metric. Every point carries project_id, corpus_version_id, variant_fingerprint and candidate_id in its payload. Its storage point ID is a deterministic UUID derived from project, corpus, variant and portable candidate identity. This keeps storage namespaces separate while exported evidence IDs remain reproducible. Every read and delete includes the exact scope. Tests must prove that an omitted or incorrect filter cannot return evidence from another project.

BM25 artifacts contain safe serialized inputs and are cached in bounded worker memory by artifact hash. Eviction affects loading latency and is reported as a cold load. A cached index cannot imply cached answers.

## PostgreSQL text snapshots

The owner supplies host, port, database, username, password and TLS mode through a protected form. Verify the destination against an explicit owner allowlist and use a dedicated read-only role. The UI selects schema, table or view, stable unique key columns, text columns and optionally updated_at.

Introspect only allowed schemas and ordinary selectable relations. Quote identifiers with the database driver's identifier-composition tools; never concatenate user identifiers into SQL. Parameterize values. The client cannot submit arbitrary SQL or connection options that trigger external execution.

Capture in a read-only repeatable-read transaction with a 30-second statement timeout and bounded fetch batches. Sort by the selected stable unique key. Take up to 10,000 rows and stop at 20 MiB serialized text. Show truncation and the deterministic first-key ordering; do not describe that subset as a representative random sample.

Selected text fields become labeled source text. Preserve the key, selected columns, relation identity, capture time and optional updated_at for citations. Nulls are represented explicitly and empty records are skipped with a count. Reject nonunique or nullable selected keys unless the user chooses another stable key. Composite keys are supported.

This source is a frozen text snapshot. Questions never reconnect to the database. Refresh captures a new source revision and corpus version. Numeric aggregation across unselected or omitted records is outside the capability of this connector.

Store only selected data. A connection-test success does not grant permission to read every table. Preview and capture use the same relation and column allowlist.

## Artifact deletion

GET source impact reports dependent corpus versions, runs, bundles and exports. Deletion requires confirmation of that exact source ID and cascade=true. Reject with RESOURCE_BUSY while dependent jobs are active.

The deletion job marks the source deleting, removes dependent content and run events, deletes derived Qdrant points and local artifacts that have no surviving references, and finally removes source bytes and marks deleted. A failed cleanup remains visible and retryable. Return metadata tombstones without retained excerpts or credentials.

Generated export archives stored by the platform are deleted when their included source data is deleted. Archives already downloaded by the user cannot be revoked; explain this in the deletion dialog.
